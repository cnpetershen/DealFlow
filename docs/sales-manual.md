# DealFlow 销售操作手册

给销售同学看的一份说明：这个系统帮你盯着线索、给你提建议，**但发出去的每一步都要你点头**。
不需要懂技术，照着做就行。技术细节在 `docs/operations.md`，本文只讲你每天用得到的。

---

## 一、三句话说清 DealFlow

1. CRM 和邮件/日历系统把「发生了什么」（新线索、客户回复了、会约上了……）告诉 DealFlow；
2. DealFlow 按跟进节奏**自动想下一步**：该发邮件了、该约会议了、该推进商机了；
3. 想到的下一步**先拿给你批**，你点批准它才执行，你拒绝它就记下来不再烦你。

一句话：**DealFlow 是你的跟进提醒 + 审批台，不是替你做决定的人。**

---

## 二、你每天只需要做三件事

| # | 事情 | 频率 | 怎么做 |
| --- | --- | --- | --- |
| 1 | 看「要我批的」 | 每天 1–2 次 | 查看待审批列表，逐条批准或拒绝 |
| 2 | 看我的名单 | 早上、收盘 | 按自己名字查线索，按阶段查商机 |
| 3 | 结掉异常 | 看到红的就处理 | 系统搞不定的事会进「异常」，你给个结论它就归档 |

其余的事（记跟进、卡时间、防止重复发送、留痕）系统自己做。

---

## 三、DealFlow 替你盯着什么

一条线索从进线到成交，系统按这个节奏提醒你：

```
新线索进来 → 提醒发第一封跟进邮件 → 客户回复了 → 提醒约会议
→ 会开上了、商机建立 → 提醒推进阶段 / 出方案 → 客户签约 → 流程自动收口
```

每个环节它都会记一笔账（谁提的建议、谁批的、什么时候发的），随时可以翻旧账复盘。

**它不会替你做的事**：

- 不会自动给新客户发邮件（**第一封永远等你批**）；
- 不会自动约会议（约会议**永远等你批**）；
- 客户说「退订」了，它会直接拦掉所有外发；
- 线索已经关闭了，它不会再打扰。

---

## 四、什么时候会跳出「要我批的」

| 系统建议 | 为什么要你批 | 你通常怎么处理 |
| --- | --- | --- |
| 发第一封跟进邮件 | 新联系人外发必须人工审核（合规要求） | 内容没问题就批准 |
| 约会议 | 见面对客户有影响，必须人工确认 | 看客户意向，批或拒 |
| 推进商机阶段（资格确认 → 发现需求） | 阶段推进不在自动放行名单里 | 确认事实无误后批准 |
| 出方案（发提案） | 涉及对外报价类材料 | 批准前自己再核一遍 |
| 再次提一个你拒绝过的建议 | 有了新事实（比如客户又建了商机），需要重新拍板 | 按新情况重新判断 |

每条建议都带**理由**，比如「Lead lead_a 已分配给 ae_wang，尚无首次跟进邮件」「客户已回复，下一步建议安排会议」。先看理由，再决定。

> 小知识：系统判断时还看「发送窗口」（默认 9:00–18:00）。晚上提交的批准不会半夜发出去，会落到窗口内执行。

## 五、一天怎么用（照着走一遍）

### 1. 早上：看我的名单

- 查我的线索：按 `owner_id` 过滤（就是你的工号/英文名，如 `ae_wang`）；
- 想看某一类：按状态过滤（`new` 新进 / `assigned` 已分配 / `engaged` 已接触 / `qualified` 已确认意向 / `nurturing` 长期培育）；
- 查我的商机：按负责人过滤，或按阶段过滤（`qualification` 资格确认 → `discovery` 需求发现 → `proposal` 出方案 → `negotiation` 谈判 → `won` 赢 / `lost` 输）。

### 2. 上午：清空「要我批的」

打开待审批列表 → 每条会告诉你：**建议做什么 + 为什么建议**。

- 同意 → 点/提交「批准」，系统立刻去执行，并开始等对方系统的回执；
- 不同意 → 点/提交「拒绝」，**必须写一句理由**（比如「客户本周出差，下周再约」）。

批准之后这条建议就消失了，流程进入「等结果」：邮件发出去了会有回执回来，系统自动接上，不用你管。

### 3. 客户有动静时：系统自己会接

客户回复邮件、日历回传「会约上了」、CRM 建了商机——这些系统自己接，接上之后它会**重新想下一步**，可能又给你弹一条待审批。

### 4. 收盘：看有没有异常、看今天批了什么

- 异常列表：系统搞不定的事（比如流程已取消、客户却又回复了）会躺在这里等你给结论；
- 审计记录：想复盘「这封邮件当时是谁批的、为什么批」，按流程 ID 一查到底。

## 六、具体怎么操作

**先说清楚**：DealFlow 现在是**接口形态，还没有网页界面**。下面的请求是给「用 Postman 之类工具点按钮」准备的，第一次可以让 IT 帮你配好一个工作区，以后就是点 Send。

统一要素（问 IT 要）：

- 地址：默认 `http://127.0.0.1:3000`（以你公司部署的为准）
- 口令：一张访问卡片（`Bearer dev-token` 这样的口令），每次请求都要带上

### 步骤 1：看待审批

```
GET  /workflows?status=needs_review
```

返回里每条都有 `workflow_instance_id`（流程编号）和 `pending_action`（待批动作），其中最重要的是 **`action_id`** —— 批准/拒绝时必须带上它，还有 `action_type`（建议做什么）和 `reason`（为什么建议）。

### 步骤 2：批准

```
POST /workflows/<流程编号>/approve
Body: { "action_id": "<上一步拿到的 action_id>", "actor_id": "你的名字" }
```

- 成功后 `pending_action` 变成空，流程状态变成「等结果」；
- 如果这条建议**已经过期**（比如客户已经流失、动作已被新情况取代），系统不会硬执行，而是自动作废它并重新想一条，返回里会标 `stale_action_replanned: true`——这是正常的，重新看待审批列表即可。

### 步骤 3：拒绝（必须写理由）

```
POST /workflows/<流程编号>/reject
Body: { "action_id": "<action_id>", "reason": "客户本周出差，下周再约", "actor_id": "你的名字" }
```

**拒绝之后会发生什么（重要）**：

- 同样的情况、同样的理由，系统**不会再拿同一条来烦你**；
- 但**不是拉黑**：一旦来了新事实（比如客户又回复了、又建了商机），它会重新提这条建议，并且明确标注「该动作此前被人工拒绝，需再次审批」；
- 所以放心拒绝，不会一拒就断，也不会拒了还自动发。

### 步骤 4：看名单 / 看商机

```
GET /leads?owner_id=ae_wang
GET /leads?owner_id=ae_wang&status=assigned
GET /leads/<线索编号>
GET /deals?stage=won
GET /deals?owner_id=ae_wang
```

列表都支持翻页（`limit` / `offset`），返回里有 `total` 和 `has_more`，不会一次把全公司倒给你。

### 步骤 5：处理异常

```
GET  /exceptions                      ← 先看有哪些（status=open 是待处理的）
POST /exceptions/<异常编号>/resolve    ← 结案
Body: { "resolution": "客户仍要采购，转人工继续跟进", "actor_id": "你的名字" }
```

- `resolution` 是**必填**的，写清楚你怎么处理的；
- `discard` 表示「这条就不该产生作用」（脏数据），用了之后这条不能反悔重放；
- `replay` 表示「把这条事实重新走一遍流程」（比如当时系统故障漏处理了）。

### 步骤 6：取消 / 复盘

- 不想再跟这条线索：`POST /workflows/<流程编号>/cancel`。取消后客户再来消息不会复活流程，但会进异常队列让你决定要不要人工接着跟；
- 复盘：`GET /audit?workflow_instance_id=<流程编号>`，按时间顺序列出「建议 → 政策判定 → 你批的 → 发送 → 结果」全链路。

## 七、常见问题（FAQ）

**Q1：为什么第一封邮件不能自动发？**
合规要求：发给新联系人的外发必须有人签过字。系统会帮你拟好、摆到你面前，你按一下就行。

**Q2：我批准了，邮件是立刻发出去吗？**
在发送窗口内（默认 9:00–18:00）会尽快发；窗口外会等到窗口开始。发送结果（成功/失败）回来后系统自动续上流程。

**Q3：拒绝时忘记写理由会怎样？**
请求会被打回，提示必须填理由。理由会写进审计，是复盘的重要信息，请认真写。

**Q4：我看到「等结果」状态，是不是卡住了？**
不是。那是系统在等对方系统回执（邮件回执、日历回执）。回执到了自动往下走；只有变成「失败」才需要你介入。

**Q5：流程「失败」了怎么办？**
系统会自动重试几次（可配置）。如果是「发出去了但不知道成没成」这种，**不要手动重复发**，让 IT/运营走「对账」确认，避免给客户发重。

**Q6：异常列表里一堆东西，我该干嘛？**
先看 `reason`（为什么进来）：
- 「流程已取消，客户又回复了」→ 你决定要不要人工接着跟，写 `resolution` 结案；
- 「找不到对应的流程」→ 多半是数据问题，转给运营/IT 核。

**Q7：能手工录一条线索 / 改客户信息吗？**
不能，控制台目前是「只读 + 审批」。录入和修改都在 CRM 里做，CRM 推给 DealFlow。

**Q8：待审批的条目批不掉、提示 409？**
说明这条动作已经不可用了（流程被取消或状态变了）。刷新看待审批列表，它应该已经不在这了；如果还显示，是已知的显示问题，以「批不动」为准。

**Q9：审批会留痕吗？谁都能看到吗？**
会。谁批的、谁拒的、理由是什么、什么时候执行的，全部写进只增不改的审计记录，可按流程查。

**Q10：我怎么知道是给谁的建议、哪家公司？**
待审批列表里带的是线索/客户编号；配合 `GET /leads/<编号>` 看公司名、联系人和当前状态。

## 八、术语小词典

| 你看到的词 | 意思 |
| --- | --- |
| 线索（Lead） | 一个潜在客户/机会的主体，可能属于你 |
| 流程 / Workflow | 这条线索的跟进进度，一条线索一个流程 |
| 建议 / 待审批动作 | 系统想做的下一步，等你批准 |
| 批准 / 拒绝 | 同意执行 / 不同意（必须写理由） |
| 等结果 | 已发出，等对方系统回执 |
| 需要人工 | 停下来等你处理（= 在「要我批的」列表里） |
| 异常 | 系统搞不定、等你给结论的事 |
| 审计 | 不能改的操作流水，用来复盘和追责 |
| 完成 / 已取消 | 流程的两个终点，之后不会再自动动 |

## 九、出问题时怎么描述（方便 IT 快速帮你）

带上这四样：

1. 流程编号（`wf_lead_follow_up_xxx`）或线索编号；
2. 大概时间点（几点批的/看到的）；
3. 你做的操作和看到的提示原文；
4. 客户/商机是哪家。

对应的后台日志关键字是 `http.access`（每个请求一行）和审计记录，IT 拿到上面四条就能直接定位。

## 十、本文对应的系统能力边界

- ✅ 看名单、看商机、看单个客户：支持，带过滤和翻页；
- ✅ 批准 / 拒绝 / 重新规划、取消 / 重试、异常结案：支持；
- ✅ 全链路留痕、可复盘：支持；
- ⚠️ 「今天我要干什么」没有一个聚合页面，需要「我的线索」+「要我批的」两条查询拼起来（已列入改进计划）；
- ❌ 手工录入/修改线索、商机：不支持，去 CRM 操作；
- ❌ 关键词搜索、批量审批：暂不支持。

更完整的评估见 `docs/sales-daily-feedback.md`。
